# 打包与安装到手机

> **给下一个 agent**：改完代码要出包/装机，直接跑
> ```bash
> bash tools/build_and_install.sh
> ```
> 脚本会把下面所有坑都替你挡掉。想搞清楚每一步在防什么，读本文。

---

## 一、最快路径

```bash
cd "/d/Accounting tool"
bash tools/build_and_install.sh
```

它会依次做 5 步，**每步都断言**，任何一步对不上就失败退出：

| 步骤 | 做什么 | 挡住了什么坑 |
|---|---|---|
| 0 | 检查 JDK / SDK / apksigner | JDK 路径写成 `/c/...` 导致 `.bat` 报 invalid directory |
| 1 | `assembleRelease` | 编译失败；warning 数量超过 0 |
| 2 | 校验签名 + 产物新旧 | 装了个签名坏掉的包；Gradle 用缓存导致装的是旧代码 |
| 3 | 同步交付物目录 | **交付物目录残留上一版**（最常见的事故） |
| 4 | `adb install -r` | 没连设备；签名冲突 |
| 5 | 拉回手机上的包比 sha256 | **无法确认手机上跑的到底是哪个包** |

### 参数

```bash
bash tools/build_and_install.sh                 # 编译 release + 同步交付物 + 装机（默认）
bash tools/build_and_install.sh --no-install    # 只打包，不装机
bash tools/build_and_install.sh --debug         # 装 debug 包（可 run-as 读数据库，调试用）
bash tools/build_and_install.sh --clean         # 先 clean（慢，但排除缓存干扰）
```

**什么时候要加 `--clean`**：改了代码但怀疑装上去的还是旧行为时。
Gradle 的增量缓存偶尔会误判，`--clean` 是最省事的排除法。

## 二、脚本为什么长这样（每个坑都真实踩过）

### 坑 1：`JAVA_HOME` 的路径形式，两种工具要求不同

这台机器的 JDK 在 `C:\Users\24996\jdk17\jdk-17.0.20.1+1`。但：

| 调用方 | 需要的形式 | 写错的后果 |
|---|---|---|
| `gradlew`（bash 脚本） | `/c/Users/24996/...` 或 `C:\...` 都行 | —— |
| `apksigner.bat`（批处理） | **必须是 `C:\...`** | `ERROR: JAVA_HOME is set to an invalid directory` |

脚本统一用 **Windows 形式**（`export JAVA_HOME='C:\Users\24996\jdk17\jdk-17.0.20.1+1'`），
两边都能用。

> ⚠️ bash 里写 Windows 路径要单引号，否则反斜杠会被当转义符吃掉。

### 坑 2：`MSYS_NO_PATHCONV=1` 不设，adb 会收到被改写的路径

```bash
export MSYS_NO_PATHCONV=1
```

不设的话，`adb pull /sdcard/s.png ./x.png` 里的 `/sdcard/s.png`
会被 MSYS 自动翻译成 `D:\sdcard\s.png`（当前盘符 + 原路径），
报错长得像：
```
adb: error: cannot create file/directory '/tmp/shots/home.png': No such file or directory
```
看起来像「目录不存在」，实际是路径被改了。

### 坑 3：⚠️ `adb` 的输出是 **CRLF** 行尾

这条最阴，因为**不报错，只是静默地判错**：

```bash
# ❌ 永远匹配不到，因为行尾是 \r，$ 锚点对不上
adb devices | grep -w 'device$' | wc -l        # 恒为 0

# ✅ 先去掉 \r
adb devices | tr -d '\r' | grep -cw 'device'
```

我写脚本第一版就踩了这个：设备明明连着，脚本却说「没有检测到设备」。
**凡是要解析 adb 输出的地方，一律先 `tr -d '\r'`。**

### 坑 4：`adb shell` 会把命令**再解析一次**

想发一条带空格的通知文本，必须套两层引号：

```bash
# ❌ 金额会被拆成多余参数丢掉，通知里只剩「支付」两个字
adb shell cmd notification post -S bigtext -t '标题' tag '支付 ¥12.34'

# ✅ 整体再包一层
adb shell "cmd notification post -S bigtext -t '标题' tag '支付 ¥12.34'"
```

我为此白查了半小时，一度以为解析引擎坏了。

### 坑 5：编译成功 ≠ 装上去的是新包

三件事必须分别确认，缺一个都可能装到旧包：

1. **产物比源码新** —— 脚本会查，加 `--clean` 解决
2. **交付物目录同步了** —— 脚本会 `cp` 并 **比对 sha256**，不一致直接失败
3. **手机上跑的确实是这个包** —— 脚本把手机上的 APK 拉回来比 sha256

第 3 条是唯一能证明「手机跑的就是刚编译那个包」的方法。
只看时间戳不可靠（安装时间 ≠ 构建时间）。

```bash
# 手工做的话是这样：
adb shell pm path com.moneyflow.app                     # 得到真实安装路径
adb pull /data/app/.../base.apk  C:\...\installed.apk
sha256sum installed.apk app/build/outputs/apk/release/app-release.apk
# 两个哈希必须一致
```

### 坑 6：不要在 mtime 上硬失败

脚本第一版在「源码比 APK 新」时直接 `fail`。结果 `touch` 一个源文件
（内容没改）会让 Gradle 判定 `UP-TO-DATE` 而不重写 APK，
mtime 检查就**永远失败**，把正常流程卡死。

现在改为：Gradle 报告 `UP-TO-DATE` 时提示一句，mtime 只作警告不阻断。

## 三、装完之后：手机上必做的三步

⚠️ **不做这三步，App 收不到任何通知，等于没装。**

1. 打开 App → 右上角 ⚙️ → **「1. 通知使用权」→ 去开启** → 找到「流水记账」→ 打开
2. 设置页 **「3. 后台运行」→ 去关闭** → 允许忽略电池优化
3. **小米/红米额外做**：
   - 设置 → 应用设置 → 应用管理 → 流水记账 → **自启动** → 打开
   - 同页 → **省电策略** → **无限制**
   - 最近任务里给本应用**加锁**

### 怎么确认真的在工作

「已开启」不代表在收通知。要分开查：

```bash
export MSYS_NO_PATHCONV=1
ADB=/c/Android/Sdk/platform-tools/adb.exe

# 静态授权（设置里那个开关）
"$ADB" shell settings get secure enabled_notification_listeners | tr -d '\r'

# 动态状态（服务是否真被系统绑上）—— 这个才是真相
"$ADB" shell dumpsys notification | tr -d '\r' \
  | sed -n '/Live notification listeners/,/Snoozed/p' | grep -i moneyflow
```

**第二条第输出为空 = 掉线了**，App 收不到任何通知。
恢复办法：去系统设置里把「通知使用权」开关**关掉再打开**
（真机实测唯一有效，详见 [真机验收记录](真机验收记录.md) 问题 1）。

命令行强制重绑：

```bash
C="com.moneyflow.app/com.moneyflow.app.capture.NotificationCaptureService"
"$ADB" shell cmd notification disallow_listener "$C"; sleep 2
"$ADB" shell cmd notification allow_listener    "$C"
```

## 四、不用手机也能验证装对了没

### 4.1 伪造一条通知，验证全链路（不花钱）

```bash
"$ADB" logcat -c
"$ADB" shell "cmd notification post -S bigtext -t '测试' tag1 '支付 ¥12.34'"
sleep 4
"$ADB" logcat -d -s NotificationCapture:V | tr -d '\r'
```

期望看到：
```
I/NotificationCapture: 已记账：其他 12.34 规则=fallback_expense
```
再发一条同金额，期望：
```
I/NotificationCapture: 重复丢弃：其他 12.34
```

### 4.2 确认 APK 里真的有你要的新代码

改了文案/新加了类，想确认**编进包里了**（而不是 Gradle 拿了缓存）：

```bash
PY=/c/Users/24996/.dsh/dsh-runtimes/dsh-primary-runtime/dependencies/python/python.exe
PYTHONIOENCODING=utf-8 "$PY" - <<'EOF'
import zipfile
apk = r"D:\Accounting tool\app\build\outputs\apk\release\app-release.apk"
z = zipfile.ZipFile(apk)
# ⚠️ 必须合并所有 dex：方法多了会拆成 classes.dex + classes2.dex，
#    只搜 classes.dex 会漏（我踩过，差点误判「新代码没编进去」）
blobs = b"".join(z.read(n) for n in z.namelist() if n.endswith(".dex"))
for s in ["已授权·未连接", "通知监听已恢复"]:
    print(f"  {s!r:24} -> {'✅ 在' if s.encode('utf-8') in blobs else '❌ 不在'}")
EOF
```

> 设备上没有 `strings` 命令，用 Python 搜 dex 最稳。

### 4.3 读数据库（release 包读不了）

release 包 `debuggable=false`，`run-as` 会拒绝：

```
run-as: package not debuggable: com.moneyflow.app
```

两个办法：

**办法 A**：装 debug 包（与 release **同一签名**，数据不丢）

```bash
bash tools/build_and_install.sh --debug
D=/c/Users/24996/AppData/Local/Temp/dsh-db; rm -rf "$D"; mkdir -p "$D"
for f in moneyflow.db moneyflow.db-wal moneyflow.db-shm; do
  "$ADB" exec-out run-as com.moneyflow.app cat "databases/$f" > "$D/$f"
done
# 三个文件必须同目录同名，WAL 才能被正确重放，然后用 Python sqlite3 读
```

⚠️ 装 debug 包会杀进程 → 监听掉线 → 用上面的 `cmd notification` 重绑。

**办法 B**（推荐给用户）：App 里 `设置 → 导出样本`，直接看 `[UNMATCHED]` 原文。

## 五、手工流程（脚本坏了时的兜底）

```bash
cd "/d/Accounting tool"
export JAVA_HOME='C:\Users\24996\jdk17\jdk-17.0.20.1+1'
export ANDROID_HOME=/c/Android/Sdk
export ANDROID_SDK_ROOT=/c/Android/Sdk
export JAVA_TOOL_OPTIONS="-Dfile.encoding=UTF-8 -Dstdout.encoding=UTF-8 -Dstderr.encoding=UTF-8"
export MSYS_NO_PATHCONV=1

# 1. 编译
./gradlew --no-daemon --console=plain clean assembleRelease

# 2. 验签
/c/Android/Sdk/build-tools/34.0.0/apksigner.bat verify --print-certs \
  app/build/outputs/apk/release/app-release.apk

# 3. 同步交付物
cp app/build/outputs/apk/release/app-release.apk "交付物/流水记账-v0.1.0.apk"

# 4. 装机
/c/Android/Sdk/platform-tools/adb.exe install -r "交付物/流水记账-v0.1.0.apk"

# 5. 验证手机上就是这个包
REMOTE=$(/c/Android/Sdk/platform-tools/adb.exe shell pm path com.moneyflow.app | tr -d '\r' | sed 's/^package://')
/c/Android/Sdk/platform-tools/adb.exe pull "$REMOTE" 'C:\Users\24996\AppData\Local\Temp\i.apk'
sha256sum '/c/Users/24996/AppData/Local/Temp/i.apk' app/build/outputs/apk/release/app-release.apk
```

## 六、签名说明（重要）

release 包**用的是调试签名**（`app/build.gradle.kts` 里
`signingConfig = signingConfigs.getByName("debug")`）。这是有意的：

- 好处：你能直接 `adb install`，也能传手机点装，不用配正式签名
- 副作用：装的时候提示「未知来源应用」；上不了应用商店
- 关键性质：**debug 和 release 是同一签名**（同一 debug keystore），
  所以两者可以互相覆盖安装且**数据保留** —— 这就是
  「装 debug 包读数据库，再装回 release」这套调试流程成立的原因

证书指纹（两个包必须一致，脚本会校验）：

```
Signer #1 certificate DN: C=US, O=Android, CN=Android Debug
Signer #1 certificate SHA-256 digest:
  c36ae256b6db9a370970380196b1833fdd91b102daf63d0e361d7524d4127e84
```

> 如果哪天换成正式签名，**换签名会导致必须卸载重装、数据丢失**，
> 而且用户装不上覆盖包。真要用正式签名，得先想好数据迁移。

## 七、发版到 GitHub Release

```bash
GH="/c/Program Files/GitHub CLI/gh.exe"

# ⚠️ 附件名不要用中文：gh 的 `文件#显示名` 语法会把中文名吃掉，
#    实测传上去变成了 "-v0.1.0.apk"。用 ASCII 名最省事。
cp "交付物/流水记账-v0.1.0.apk" 'C:\Users\24996\AppData\Local\Temp\moneyflow-v0.1.0.apk'
"$GH" release create v0.1.0 \
  'C:\Users\24996\AppData\Local\Temp\moneyflow-v0.1.0.apk' \
  --title "流水记账 v0.1.0" --notes "见 docs/真机验收记录.md"
```

> 推送/发布时若报 `schannel: CRYPT_E_NO_REVOCATION_CHECK`，
> 是网络无法校验证书吊销状态（国内常见），执行一次：
> `git config --global http.schannelCheckRevoke false`

## 八、一句话总结

**别手工敲命令，跑 `bash tools/build_and_install.sh`。**
它把 6 个坑都固化成了断言，包括那个「adb 输出是 CRLF 所以 grep 匹配不到」
的静默陷阱 —— 那个坑不报错，只会让你以为手机没连上。
